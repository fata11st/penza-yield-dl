# CLAUDE.md — правила для ИИ-агента в penza-yield-dl

Язык общения, комментариев, документов — **русский**. Подробности: `docs/PLAN.md`, `docs/ENVIRONMENT.md`.

## Что это

Научная статья (ВАК, 8–10 с.): методы глубокого обучения для прогнозирования урожайности пяти культур Пензенской
области на датасете 1990–2025 (n = 36 лет) и сравнение с Ridge-регрессией из двух предыдущих статей авторов.
Университетская работа (ПГУ, ПГАУ), не проект ООО «Шэдоухарт» и не часть `ml-lab`.

## Инварианты

1. **Без утечки из будущего.** Прогноз на год t — только по данным до t (внутрисезонный — до месяца отсечки).
   Масштабирование, отбор признаков, подбор гиперпараметров — внутри окна обучения. Тесты в `tests/test_validation.py`.
2. **Годы оценки 2019–2025 заморожены**: подбор чего-либо только на 2011–2018 (`validation.TUNE_YEARS`).
3. **Датасет не меняется молча**: SHA-256 в `data.py`; новая версия — только с записью в `docs/DECISIONS.md`.
4. **Не выдумывать числа.** В тексте статьи — только из файлов `experiments/…`, с путём. Нет файла — `[уточнить]`.
5. **Не повторять таблицы и формулировки прошлых статей** (самоплагиат): датасет и Ridge — кратко, со ссылками.
6. **Итоговые сравнения — по нескольким seed**, с доверительными интервалами и тестом Диболда–Мариано.

## Где выполняются команды

ПК `Zver` (Ryzen 9 9900X, 64 ГБ, RTX 5070 Ti 16 ГБ), Windows 11 + WSL2. Пользователь работает за самим ПК.
- **«Ubuntu `penza-dl`»** — почти всё: код, окружение, расчёты. Пользователь `pnz`, проект `~/projects/penza-yield-dl`.
- **«PowerShell»** — только Windows. Из `penza-dl` команды Windows недоступны (interop выключен).
- Инструкции — по одному шагу, каждый блок с меткой места, ожидаемый результат, просьба прислать вывод.
  **Каждая команда — в отдельном блоке кода**, одной строкой; без `cat <<EOF` (ломается при копировании).

## Соседи — не мешать

В той же виртуальной машине WSL работают **сервер toraX** (`Ubuntu-24.04`, медицинский сервис, работает круглосуточно)
и **`ml`** (эксперименты). Общие: 40 ГБ ОЗУ, CPU, сеть (`mirrored`), GPU.
- **Никогда `wsl --shutdown`** — остановит сервер. Перезапуск своей машины: `wsl --terminate penza-dl`.
- `.wslconfig` общий — не менять без согласования (29.10.2026 его однажды затёрли; восстановлен из теневой копии).
- Порты 22, 80, 443, 5432, 8000, 8080, 8443 (сервер), 2222 (`ml`) не занимать. Наши — в `configs/resources.yaml`.
- Лимиты CPU/памяти/GPU — `configs/resources.yaml`; в каждом скрипте `resources.apply_limits()`;
  долгие запуски — `tools/run_limited.sh` внутри `tmux`.
- На GPU постоянно работает воркер toraX (~1,7 ГБ) — это норма, его не трогать. Перед долгим запуском на GPU
  спросить у пользователя, не идёт ли обучение в `ml`.

## Как работать

- Изменения — через ветки и PR в `fata11st/penza-yield-dl`; пользователь сливает и делает `git pull` в `penza-dl`.
- Решения (архитектура, протокол, отказ от подхода) — в `docs/DECISIONS.md` с причиной.
- Версии библиотек и совместимость с CUDA — проверять по актуальным источникам. PyTorch — только `cu130`.
- Документы для соавторов — копией в Google Drive, папка «penza-yield-dl — урожайность, глубокое обучение».
